    左の一覧から開いた記事がここに表示されます。

    この原型では、各記事に path を持たせて、ディレクトリ単位で管理する前提にしています。 たとえば posts/research/thermal/lhp.md のように置けば、サイト上でもその所属が分かります。

    例: \(E = mc^2\) や $$\int_0^1 x^2\,dx = \frac{1}{3}$$

    管理の考え方

    タグは補助情報として使い、主分類はディレクトリに任せる構成です。 すると、研究メモ・旅行記・技術記事のような“内容の置き場所”が明確になります。

    ディレクトリ構成の例

    repo/
├─ index.html
├─ assets/
│  ├─ css/
│  └─ js/
└─ posts/
   ├─ research/
   │  ├─ thermal/
   │  │  ├─ 2026-07-26-lhp.md
   │  │  └─ 2026-07-24-cpl.md
   │  └─ mission/
   │     └─ 2026-07-20-dsotv.md
   ├─ dev/
   │  └─ 2026-07-18-github-pages.md
   └─ diary/
      └─ 2026-07-15-trip.md

    この形なら、プログラム上でも path の先頭部分で分類しやすく、サイト上でもフォルダツリーとして見せやすいです。

    この原型でやっていること

    主分類はフォルダ記事の意味をタグではなく配置で表します。
    CSS は変数中心色・余白・角丸をまとめて変更できます。
    記事は path で管理プログラム側でも扱いやすいです。
    数式はそのままMathJax で LaTeX を表示できます。

    拡張するときの方針

    • 記事本文を Markdown に分離する
    • posts/ 配下をフォルダ単位で読み込む
    • 各記事の front matter に title, date, path を持たせる
    • 一覧はフォルダ階層で折りたたみ表示にする
